# Jekyll → Hugo migration

Pre-publication validation recorded 1 November 2026 on `site/hugo-migration`. This document records the migration scope, local checks and publication checklist.

## Scope

The migration starts from the approved redesigned Jekyll working tree, including its uncommitted changes, rebased onto main at `143fc62`, including its v1.8.3 release notes. Its original checkout and a separate source/rendered snapshot were preserved.

All 234 existing HTML routes are retained. The native site contains 233 non-homepage pages plus English and Spanish homepages. These include all 160 canonical documentation pages, the 118-route legacy inventory, showcase pages/forms, the workshop and worksheet redirects, and the internal manual review page. The latter remains available but is excluded from search and marked noindex.

The approved design, credits, screenshots, animations, video integration and copy are retained. The Spanish title is **Planea el recorrido de la historia**, with its former anchor preserved. The native Spanish homepage is `/es/`; old `?lang=` links forward while preserving the section fragment.

## Native implementation

Content is authored in Hugo's English and Spanish directories. Existing published URLs are explicit in front matter, and `translationKey` supplies native pairing. Shared data controls editorial navigation order, labels and media; the duplicate per-page title/translation registry is removed.

The three shared page shells use native Go templates. Includes for diagrams, media, callouts and repeated guide content use shortcodes. Interactive configuration tools and showcase browser code are retained as source components. No Jekyll-generated page body is embedded in the site. The former Ruby/theme/Sass build has been removed from this worktree.

Metadata, canonicals, language alternates, sitemaps and robots rules are generated by Hugo. Local builds use a separate preview configuration. Search indexes all 160 guide pages in two languages. The build uses pinned Hugo Extended 0.160.1 and Pagefind 1.5.2 dependencies installed by `npm ci`, without referencing another repository's tools.

The production service addresses remain the existing showcase Worker. Local integration testing uses a separate Worker copy, database and test Turnstile keys, with no Slack destination. The documented preview harness was started successfully against the separate Worker checkout.

## Validation

- Clean `npm ci` succeeded.
- Production: **20,441 checks; zero failures**.
- Preview: **20,370 checks; zero failures**.
- Source-to-output comparison: all 233 non-homepage pages and 160 canonical docs; **zero outstanding differences** under the recorded comparison rules.
- Every existing served HTML route and all 118 legacy inventory entries remain available. Internal links, fragments, heading aliases, image targets and alt attributes pass.
- Browser testing covered language pairing, both searches, slash/Escape search navigation, the configuration tools, math rendering, the gallery and both forms. English and Spanish teaching requests and one showcase request were stored locally. The three local notification jobs had zero delivery attempts and no sent timestamp.
- Seven representative pages were measured at 390×844 and four at 768×1024. None had page-level horizontal overflow. The viewport capability affects the selected browser tab, which was explicitly verified before recording these results.
- `git diff --check` passed. The prepared GitHub workflow has not yet run on GitHub.

Machine-readable inventory and evidence are in `migration/`. Fresh test results are written to the ignored `reports/` directory. Route/content contracts are snapshots for regression checking; they are not runtime dependencies or copied page bodies.

## Rendering and tool corrections

The port preserves Kramdown heading IDs explicitly, converts callout annotations, supplies Chroma styles for native highlighting, and renders the approved HTML in quick-guide data as HTML. Large interactive HTML forms use native source components so CommonMark does not reinterpret their indentation as code.

Two existing configuration-tool bugs were corrected during browser testing: the generator quoted its version/date twice, producing invalid YAML; and the validator did not recognise the existing `trama` theme. The generator now emits valid quoted values and the validator accepts all five installed theme names. No surrounding instructional wording was rewritten.

One precisely recorded prose comparison exception covers stray visible Markdown delimiters around the Spanish “View full site” troubleshooting label. Hugo formats the unchanged words correctly. This is a rendering correction, not a new translation.

## Publication checklist

1. Review the complete local site at port 4004. The remaining Spanish editorial batches remain separate from this technical migration.
2. Commit and push the migration branch when ready, then run the prepared pull-request build on GitHub. Remote CI and production deployment have not been exercised here.
3. After the review and checks, merge to switch the existing Pages build to Hugo. No DNS or hosting migration is needed for the proposed workflow.
4. Verify the live language homepages, old workshop links, search, gallery, Vimeo and both forms. Any live notification test should be deliberate; this migration's tests did not send notices.
5. For rollback, restore the pre-release source/workflow commit or redeploy the previous Pages artifact. The old Jekyll working tree remains available locally for comparison.

Telar exhibition sites and the Compositor's application build are unchanged by this documentation-site migration.
