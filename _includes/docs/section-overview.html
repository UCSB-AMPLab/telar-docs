La autoría con Google Sheets te permite crear una exhibición en Telar desde una hoja de cálculo compartida. Registras tus fuentes, organizas los pasos de las historias y escribes los textos en filas y columnas; Telar lee ese contenido y genera el sitio web.

Esta forma de trabajo es útil si prefieres editar en una hoja de cálculo, revisar varios registros a la vez o escribir con un equipo. La hoja reúne el contenido narrativo y los metadatos. Las imágenes y los demás medios se cargan desde sus direcciones de origen o desde los archivos del sitio.

Cómo se organiza la hoja de cálculo

  • objects reúne el catálogo de fuentes, con sus descripciones, créditos y direcciones.
  • project enumera las historias y define su orden en la exhibición.
  • Cada historia tiene su propia pestaña. Cada fila corresponde a un paso y relaciona el texto con un objeto, su encuadre y sus paneles.
  • glossary define términos que puedes enlazar desde los textos.

Cómo funciona

  1. Prepara el sitio y la hoja. Crea un repositorio de Telar en GitHub, copia la plantilla de Google Sheets y conecta su dirección publicada con el sitio.
  2. Escribe y organiza. Registra objetos, agrega historias y pasos, y desarrolla los textos. Usa el visor del sitio para elegir los encuadres.
  3. Genera y revisa. Ejecuta el proceso de generación en GitHub para incorporar el contenido actualizado de la hoja. Abre el sitio y comprueba el resultado.

Editar una celda no actualiza de inmediato el sitio público. Cada generación lee la versión publicada de la hoja y produce una nueva versión de la exhibición.

Antes de comenzar

Necesitas cuentas de Google y GitHub. La configuración guiada te acompaña desde la copia de las plantillas hasta la conexión del sitio y genera el archivo de configuración. Si todavía estás desarrollando la narrativa, empieza por Planear una exhibición.

The Google Sheets workflow lets you author a Telar exhibition in a shared spreadsheet. You catalogue your sources, arrange story steps and write narrative text in rows and columns; Telar reads that content and builds the website.

This approach suits people who prefer a spreadsheet, want to review several records at once or write with a team. The sheet brings together narrative content and metadata. Images and other media load from their source addresses or from files in your site.

How the spreadsheet fits together

  • objects holds your source catalogue, including descriptions, credits and addresses.
  • project lists the stories and sets their order in the exhibition.
  • Each story has its own tab. Each row is a step, connecting text to an object, its framing and its panels.
  • glossary defines terms you can link from your text.

How it works

  1. Set up the site and sheet. Create a Telar repository on GitHub, copy the Google Sheets template and connect its published address to the site.
  2. Write and arrange. Catalogue objects, add stories and steps, and develop the text. Use the site's viewer to choose image framings.
  3. Build and review. Run the build on GitHub to bring in the updated sheet content. Open the website and check the result.

Editing a cell does not immediately update the public site. Each build reads the published sheet and produces a new edition of the exhibition.

Before you begin

You need Google and GitHub accounts. The guided setup takes you from copying the templates to connecting the site and generates your configuration file. If you are still developing the narrative, begin with Plan an exhibition.

La autoría local consiste en editar los archivos de tu exhibición en tu computador y generar allí una vista previa. Trabajas con archivos CSV y Markdown en el editor que prefieras y usas las herramientas de Telar para convertirlos en un sitio web.

Elige esta forma de trabajo si quieres acceso directo a los archivos, personalizar el sitio o controlar el proceso de generación y el alojamiento. El resultado es un sitio estático que puedes publicar en GitHub Pages o en otro servidor web.

Los archivos con los que trabajas

  • CSV: tablas en texto plano para el catálogo de objetos, la lista de historias, los pasos y el glosario.
  • Markdown: archivos de texto para paneles extensos, entradas del glosario y páginas de apoyo.
  • Archivos de medios: imágenes y otros materiales que alojas en tu sitio. También puedes referenciar objetos IIIF y medios alojados en otras colecciones.
  • Configuración: archivos que definen el título, el idioma, el tema y la navegación del sitio.

Cómo funciona

  1. Prepara una copia local. Obtén los archivos de Telar e instala las herramientas necesarias para generar el sitio.
  2. Edita y previsualiza. Agrega las fuentes, escribe las historias y genera una vista previa en tu navegador. Repite este proceso para revisar los encuadres, los textos y los enlaces.
  3. Publica. Envía los cambios al repositorio de GitHub para generar el sitio público o aloja los archivos generados en el servidor que elijas.

La vista previa local te permite revisar el trabajo antes de publicarlo. Conserva los archivos de autoría: son la fuente para las revisiones y las futuras versiones del sitio.

Antes de comenzar

Debes poder trabajar con carpetas, editar archivos de texto y ejecutar comandos en una terminal. La guía de instalación explica las herramientas necesarias: Ruby, Python, Node.js y Git. Si todavía estás desarrollando la narrativa, empieza por Planear una exhibición.

Local authoring means editing your exhibition's source files on your computer and generating a preview there. You work with CSV and Markdown files in your preferred editor and use Telar's tools to turn them into a website.

Choose this approach if you want direct access to the files, want to customise the site or need control over building and hosting it. The result is a static site you can publish on GitHub Pages or another web server.

The files you work with

  • CSV: plain-text tables for the object catalogue, story list, steps and glossary.
  • Markdown: text files for longer panels, glossary entries and supporting pages.
  • Media files: images and other materials hosted by your site. You can also reference IIIF objects and media hosted by other collections.
  • Configuration: files that define the site's title, language, theme and navigation.

How it works

  1. Set up a local copy. Get the Telar source files and install the tools needed to build the site.
  2. Edit and preview. Add your sources, write stories and build a preview in your browser. Repeat as you check framings, text and links.
  3. Publish. Send changes to your GitHub repository to build the public site, or host the generated files on your chosen server.

The local preview lets you review the work before publishing. Keep your editable source files: they are the starting point for revisions and future editions of the site.

Before you begin

You should be comfortable working with folders, editing text files and running commands in a terminal. The installation guide covers the tools you need: Ruby, Python, Node.js and Git. If you are still developing the narrative, begin with Plan an exhibition.
